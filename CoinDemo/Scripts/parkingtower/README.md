# 주차타워 PLY 역분석 (Parking Tower reverse study)

질문: **"원본 PLY 자체가 고품질인가, 아니면 언리얼 작업(메시·재질·조명)이 최종 영상을 고품질로 보이게 만든 것인가?"**

결론부터: **감독 영상(`parking-tower/video.mp4`)은 이 PLY를 표준 3DGS 뷰어로 그대로 렌더링한 것 + 2D/3D AR 오버레이(초록 주차칸 상자, 하늘색 경로 화살표, "주차 가능/목적지 도착" 라벨)입니다.**
메시·PBR·조명 추가 흔적은 없습니다. 고품질의 원인은 **데이터(촬영·학습 품질)** 입니다. (근거와 수치는 아래)

`Referense/롯데타워_빈자리네비게이션.mp4`는 **다른 장소**(지하 주차장, 기아 EV9 등 차량 3D 모델, 내비 UI)이고 완전한 CG(언리얼 모델링) 영상이라 이 스캔과 매칭되지 않습니다. 비교 대상에서 제외했습니다.

## 1. 데이터 확인 (확정)

- `scene.compressed (2).ply` 183 MB: 헤더 `comment Generated by ANNX AI EDITOR 1.9.0`, `element chunk 11689`, `element vertex 2,992,374`(packed uint32 ×4), `element sh`(uchar ×45) → **SuperSplat 형식 압축 PLY, 진짜 3DGS(포인트 클라우드 아님), SH 3차**. 해제본 742 MB.
- 해제 검증: 표준 3DGS로 `settings (3).json`의 초기 카메라를 그리면 `thumbnail (3).png`와 사실상 같은 그림. (회전 성분 순서를 (x,y,z,w)로 읽으면 바늘 모양 잡티가 생겨 PLY 순서(w,x,y,z)로 확정)
- `settings (3).json`: SuperSplat 공개(Publish) 설정. `tonemapping: none`, 그레이딩·블룸·샤픈·비네트 **모두 꺼짐**, 카메라 fov 75(세로), 배경 회색 0.47.
- `video.mp4`: 1920×1080 60fps 24초, 컷 3번(5.0 / 11.0 / 19.0초)으로 4개 샷.

## 2. PLY 분석 (`analysis/stats.txt`, `stats.json`)

좌표계·축척 (측정 = 확정, 축척값 자체는 추정 ±8%)
- 위쪽 축: PLY **−Y** (Y 분포가 5~95% 구간 2.8단위로 가장 좁음). 홍대와 같은 COLMAP 계열 → OpenSplat4D 변환 `UE = (z, x, −y)·100` 그대로, Actor 회전 없음.
- 바닥면: 바닥 평면 잔차 1.6cm(단위 0.016). 단, 한쪽 끝이 다른 끝보다 약 0.4m 낮고 천장 조명 높이도 같은 방향으로 0.45m 기울어 → **스캔 전체가 긴 축으로 약 0.8° 기울어짐**(중력 정렬 오차로 추정; 실제 구조물 경사일 가능성은 낮음).
- 축척: 주차칸 선 간격 0.65단위(FFT/피크 반복) → 칸 폭 2.5m 기준 **3.846 m/단위**(2.3m 기준이면 3.54). 교차 검증: 세워진 골프(실제 4.26×1.80m) 차체 3.86×1.82m, 천장 설비층 2.5~3.0m, 슬래브 하부 3.3m → 일관됨.
- 언리얼 배치: 스케일 3.846, 위치 Z −76cm(덱 중앙 바닥 = Z 0). 주차층 X −43~37m, Y −15~15m(약 31×80m). 기둥 10.3m 간격 3열(언리얼에서 약 −3.8° 회전).

해석
- 주차타워는 **불투명한 스플랫이 많고(중앙값 5배), 바닥이 2배 촘촘·2배 작은 스플랫, SH 3차로 시점 의존 색(반사·광택)이 4배 강함.** 홍대는 희미한 스플랫을 여러 겹 쌓은 구조라 어떤 렌더러로도 흐릿합니다.
- 반사: 에폭시 바닥의 광택·기둥 반사는 PLY 안에 들어 있습니다. 바닥 아래(거울 세계) 스플랫 + SH. 단면도(`analysis/parking_section.png`)에 바닥 밑으로 비친 주황 기둥이 보입니다. 위에서 보면 통로 바닥층(±5cm)은 대부분 반투명하고(덮임 0.43), 페인트 선·화살표·횡단보도만 불투명 → 일반 바닥의 "젖은 듯한" 외관은 여러 층 + 시점 의존 색의 결과입니다.
- 손상·빈 곳: 촬영 경로(통로) 밖 — 바깥 난간 쪽 바닥, 주차칸 깊숙한 곳, 덱 양 끝 — 은 번지고 길쭉한 스플랫(`abc/generic_04.jpg` 외곽 바닥). 가까이(1~2m) 내려다본 바닥은 원본 렌더러로도 흐릿하고 얼룩(`abc/generic_03.jpg`).
- 덱 바닥 덮임 지도: `analysis/ground_coverage_scene.png` (주차타워), `ground_coverage_Hongdae.png` (홍대). 육안 비교: `analysis/hongdae_raw_vs_parking_raw.jpg`.

## 3. 원본 PLY만 렌더링: A / B / C (`abc/`, `steps/`)

- A = 원본 + 플러그인 기본(FXAA, `gs.ToneCorrection 0`), B = 원본 + CoinDemo 개선(TSR, `gs.ToneCorrection 1`), C = 표준 3DGS 기준 렌더러. 1600×900, 수평 90°, 같은 카메라.

| 시점 | C 선명도 | A 선명도 / 색오차 / 중간톤 | B 선명도 / 색오차 / 중간톤 |
|---|---|---|---|
| 영상 시작 지점(횡단보도) | 225 | 104 / 0.098 / ×0.77 | 151 / 0.046 / ×0.93 |
| 천장 올려보기 | 4.4 | 4.5 / 0.065 / ×0.79 | 8.3 / 0.025 / ×0.99 |
| 바닥 근접(기둥 옆) | 2.4 | 2.0 / 0.098 / ×0.75 | 5.7 / 0.039 / ×0.93 |
| 바깥 난간 쪽 | 83 | 52 / 0.077 / ×0.75 | 84 / 0.036 / ×0.95 |
| 북쪽 통로 4곳(steps) 평균 | – | 색오차 0.089, 중간톤 ×0.77 | 색오차 0.035, 중간톤 ×0.95 |

- **홍대에서 측정한 톤 LUT(`gs.ToneCorrection 1`)가 이 스캔에도 맞습니다**: 중간톤 ×0.75~0.79 → ×0.93~0.99, 색 오차 절반 이하. LUT는 장면이 아니라 플러그인 합성(역 ACES)과 언리얼 톤매퍼의 불일치를 고치는 것이라 장면이 바뀌어도 유효. 남은 오차: 중간톤 약 5% 어두움.
- FXAA는 선명도를 기준 대비 약 45~55%로 떨어뜨림(홍대 −20%보다 큼: 이 스캔은 디테일이 많아서). TSR로 65~100%.
- `r.ScreenPercentage=150`(+TSR): 선명도가 기준 수준(234 vs 225)까지 올라가지만 FPS 191 → 92. AA 끔은 TSR과 거의 같음(정지 화면 기준).

## 5. 제작 방식 역추정

| 분류 | 요소 |
|---|---|
| (1) 원본 PLY로 가능 | 바닥(페인트 선, 광택, 반사), 기둥, 천장·배관·조명, 차량, 표지판, 야경, 조명·그림자(구워짐) — **영상 화면의 거의 전부** |
| (2) 렌더링/그레이딩으로 설명 | 톤매핑 없음(settings.json), 수평 약 64° 화각·1m 높이의 차량 시점, 부드러운 가속 카메라 경로 |
| (3) 추가 정적 메시/PBR 필요 | 없음(영상에서). 단, 우리 언리얼에서 근접 바닥 디테일을 원하면 필요 |
| (4) CAD/모델링/추가 촬영 필요 | 없음(영상에서). 촬영 경로 밖(난간 쪽 바닥, 칸 안쪽)을 근접해서 보려면 추가 촬영 |
| (5) 판단 불가 | AR 오버레이를 어떤 도구로 합성했는지(영상 편집 vs 뷰어 내 3D 그래픽), 촬영 장비·학습 소프트웨어(ANNX 외) |

확정 vs 추정
- 확정: PLY 형식·SH 3차·ANNX 생성, 영상 프레임 = 원본 PLY 표준 렌더(색 오차 0.017, SSIM 0.92), 톤매핑·그레이딩 꺼짐, 반사가 PLY에 있음.
- 추정: 축척 3.846(±8%), 스캔 0.8° 기울기의 원인, 샷 3·4의 정확한 위치(맞춤 품질 표 참고), 오버레이 제작 도구.
- 고품질의 원인(추정, 근거 있음): 실내·고정 조명·반복 구조라 촬영 조건이 좋고, 운전자 높이로 통로를 촘촘히 촬영 → 촬영 경로 위에서 보면 거의 사진. 홍대(야외, 시간대·사람·차량 변화, 넓은 영역)보다 학습이 쉬운 장면.

## 질문별 답

1. **홍대 PLY와 품질 차이**: 같은 ANNX 출신이지만 주차타워가 확실히 좋음. 불투명도 중앙값 0.30 vs 0.063(5배), 불투명 스플랫(>0.9) 12.6% vs 0.07%, 바닥 스플랫 2배 촘촘(214 vs 114/㎡)·2배 작음(4.3 vs 7.7cm), SH 3차 vs 1차(시점 의존 색 4배). 실내·고정 조명·운전자 높이 촘촘한 촬영이라 촬영 경로 위에서는 거의 사진 수준. 단 경로 밖(난간 쪽, 칸 깊숙이, 근접 바닥)은 홍대처럼 번짐.
2. **원본 PLY만으로 감독 영상에 접근 가능?**: **예. 감독 영상 자체가 원본 PLY 렌더링**(같은 카메라에서 색 오차 0.018, SSIM 0.92~0.93). 언리얼에서도 TSR + `gs.ToneCorrection 1`만으로 영상 대비 색 오차 0.03, SSIM 0.89~0.90(화각 맞추려 잘라 확대한 손실 포함).
3. **PLY에 없는 디테일**: 근접(1~2m) 바닥의 미세 질감(얼룩처럼 뭉개짐), 경로 밖 영역(난간 쪽 바닥·칸 안쪽·덱 양 끝), 촬영 중 움직인 물체(반투명 차·사람), 유리·차창 반사의 정확도. 위에서 본 일반 바닥은 반투명 층이라 위/아래 시점에서 비침. 페인트 선 가장자리는 약 2~4cm 해상도.
4. **고품질에 가장 기여한 것**: 데이터. (a) 촬영·학습 품질(불투명하고 작은 스플랫, SH 3차로 광택·반사까지 학습), (b) 촬영 경로와 같은 높이·방향으로만 카메라를 움직인 연출(경로 밖 약점을 안 보여줌), (c) 톤매핑 없는 렌더(색이 그대로). 메시·PBR·언리얼 조명은 쓰이지 않음(확정). AR 오버레이가 "제품" 느낌을 더함.
5. **현재 CoinDemo 기술로 재현 정도**: 레벨 `Lvl_ParkingTower_ReverseStudy` + TSR + 톤보정으로 샷 1·2 화면을 사실상 재현(위 수치, 191fps). 남은 차이: 중간톤 약 5% 어두움(LUT가 홍대 기준), 선명도 기준 대비 65~100%(150% 해상도면 같아지나 92fps), 화각(DevCapture 90° 고정 → 영상은 64°, 게임 카메라에서 바꾸면 됨). AR 오버레이(주차칸 상자·경로)는 별도 구현 필요(스캔과 무관).
6. **추가 모델링/데이터가 필요한 것**: 영상 재현에는 없음. 게임·자유 시점용으로는 바닥 충돌(높이장, 이번에 만든 바닥 메시 재사용 가능), 근접 바닥 디테일(PBR 바닥은 반사가 사라지는 대가), 경로 밖 영역(추가 촬영), 움직인 물체 정리(유령 차·사람 제거). 기둥·천장을 단순 메시로 바꾸는 것은 품질을 떨어뜨림(E5).
7. **홍대 스캔에 적용 가능?**: 렌더러 쪽(TSR + 톤보정 LUT)은 이미 적용됨(`Lvl_Hongdae_HighQualityGS`), 같은 효과. 그러나 주차타워 수준의 결과는 **데이터 차이라서 홍대에 같은 방법을 써도 안 나옴**(희미한 다층 스플랫, SH 1차, 야외·넓은 영역). 홍대를 이 수준으로 하려면 같은 방식의 재촬영/재학습(SH 3차 유지, 걷는 높이로 촘촘히, 경로를 정해 촬영)과 영상에서 카메라를 촬영 경로에 묶는 연출이 필요. 메시 하이브리드는 홍대에서도 정면 시점에서는 원본과 비슷하거나 약간 나빴음(HANDOFF 3-7, 3-8)과 같은 결론.

## 한계
- 축척은 주차칸 폭 2.5m 가정(2.3m면 −8%). 차량·천장 높이로 교차 확인만 함.
